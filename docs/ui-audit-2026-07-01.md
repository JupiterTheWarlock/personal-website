# 个人网站 UI 审查报告

审查日期：2026-07-01  
审查对象：`personal-website` 最新 `origin/main`，提交 `b35fc88`  
审查方式：本地 Next 预览、桌面 1440x1000、移动 390x844 视口截图、滚动定位数据、生产构建检查。

## 结论

现在的网站不是“整体不能用”，而是几个基础布局问题把体验拉坏了：

1. 移动端已经真实破版：390px 视口下页面实际宽度是 511px，出现横向滚动条，About、Sites、Projects section 会被左侧裁掉。
2. “PPT 翻页”不是一屏一页：1000px 高桌面视口下 section 高度约 1192px 到 1224px，844px 高移动视口下 section 高度约 1036px 到 1144px，滚动距离和用户预期不一致。
3. 首屏木星确实太不明确：背景层 opacity 只有桌面 0.1、移动 0.06，同时木星又和标题、右侧 console 重叠，结果既不够强，也干扰内容层级。
4. 首屏信息太挤：桌面右侧 console 和主标题抢主视觉；移动端导航占两行，标题拆行不受控，console 被塞在首屏后半，导致第一屏不像一个干净封面。

建议不要重写整站。先用一轮小 CSS 和布局调整把“破版、翻页、首屏构图”修掉，再决定是否做更大的视觉升级。

## P0：先修移动端横向破版

问题表现：

- 390px 下底部出现横向滚动条。
- About、Sites、Projects 的左侧内容被切掉。
- Header 里的“项目”在右侧被截断。
- Sites 和 Projects 在窄屏仍试图维持多列卡片，导致卡片容器被撑到视口外。

根因位置：

- `components/content/SectionCard.tsx:17` 用固定长度 `─`.repeat 生成 `pre` 标题线。
- `app/globals.css:513` 的 `.sites-grid` 使用 `minmax(260px, 1fr)`。
- `app/globals.css:576` 的 `.projects-grid` 使用 `minmax(220px, 1fr)`。
- `.content-section` 是 flex 容器，子项缺少 `min-width: 0`，会被 min-content 撑宽。

建议做法：

1. 去掉固定长度 ASCII 横线，或者让它只作为 CSS border/background，不参与布局宽度。
2. 给 section 内层 wrapper 和 card 加 `min-width: 0; max-width: 100%;`。
3. 改 grid 写法，让列宽不超过容器：

```css
.content-section > .w-full {
  min-width: 0;
  width: min(100%, 48rem);
}

.section-card,
.section-card-content,
.section-card-header {
  min-width: 0;
}

.section-card-header pre {
  max-width: 100%;
  overflow: hidden;
  white-space: nowrap;
}

.sites-grid,
.projects-grid {
  grid-template-columns: repeat(auto-fit, minmax(min(100%, 220px), 1fr));
}
```

这是第一优先级。它修完之前，其他视觉调整在手机上都会被横向溢出污染。

## P1：重新定义“PPT 翻页”

问题表现：

- 现在每个 section 设置了 `scroll-snap-align: start`，但 section 自身高度大于 viewport。
- 用户感觉像翻页，但每页不是一屏，滚动停点和视觉中心不一致。
- 固定 header 高度没有进入 snap 计算，未来如果 nav 滚到某个 section，section 顶部会被 header 盖住。

根因位置：

- `app/globals.css:26`：`html { scroll-snap-type: y mandatory; }`
- `app/globals.css:148`：`.content-section { min-height: 100vh; padding: 6rem 2rem; }`
- `app/globals.css:155`：`scroll-snap-align: start`
- `app/globals.css:381` 之后移动 header 变成两行，实际 header 高约 101px。

建议先二选一：

方案 A，保留 PPT 风格：

- section 用 `min-height: 100svh`，减少上下 padding。
- 给 `html` 加 `scroll-padding-top`，按 header 高度留出定位补偿。
- 对内容很长的 section 不强行居中，避免内容溢出一屏。
- 给 section 加明确 `id`，让导航真的滚到对应段落。

方案 B，放弃强制 PPT 翻页：

- 桌面可以保留轻量 snap，移动端直接关闭 snap。
- 内容按正常长页面滚动，体验更稳定。

我建议选 B，成本更低。个人网站不是演示 deck，移动端强制 snap 的收益不大。

最小修法：

```css
html {
  scroll-padding-top: 5rem;
}

.content-section {
  min-height: 100svh;
  padding: 5.5rem 2rem 3rem;
}

@media (max-width: 860px) {
  html {
    scroll-snap-type: none;
  }

  .content-section {
    min-height: auto;
    padding: 7.5rem 1.25rem 3rem;
  }
}
```

## P1：首屏和木星需要重新分层

问题表现：

- 木星太暗，桌面 opacity 是 0.1，移动端是 0.06。
- 木星主体和环穿过标题、右侧 console、后续 card 背后，视觉上像噪声。
- 桌面首屏上方空白偏大，主体内容从约 398px 才开始。
- 移动端标题拆成“术士木 / 星”，不是设计过的换行。

根因位置：

- `app/globals.css:52`：`.ascii-background { opacity: 0.1; }`
- `app/globals.css:377`：移动端 `.ascii-background { opacity: 0.06; }`
- `components/three/JupiterScene.tsx:14`：`RIGHT_EDGE_OFFSET = 4`
- `components/three/JupiterScene.tsx:64`：木星中心按右边缘锚定。
- `components/content/HomeContent.tsx`：hero 同时放主文案、CTA、右侧 live_index console。

建议做法：

1. 木星只在 hero 里做强主视觉，后续 section 降低或隐藏。
2. 桌面把木星移到更明确的右侧视觉区，不要穿过 H1 主体。
3. 给文字区域加非常克制的暗色遮罩或背景渐变，保证可读性。
4. 移动端不要显示完整巨大木星，可以只留局部纹理或降低到背景氛围。
5. 把右侧 console 从首屏主视觉里降级，放到 hero 下方或改成一条简短 project ticker。

推荐目标：

- 桌面：左侧是名字、定位、CTA；右侧是清晰可识别的木星。console 不再和木星抢位置。
- 移动：第一屏只保留名字、定位、CTA 和一点木星纹理，不放完整 console。

可接受的最小 CSS 调整：

```css
.ascii-background {
  opacity: 0.18;
}

@media (max-width: 860px) {
  .ascii-background {
    opacity: 0.1;
  }

  .hero-console {
    display: none;
  }
}
```

如果只加 opacity，不移动木星，桌面右侧会更乱。所以更好的做法是同时调 `RIGHT_EDGE_OFFSET` 和 hero 文案宽度。

## P2：Header 在移动端信息过载

问题表现：

- 移动端 header 两行，语言按钮和 nav 同时占首屏高度。
- “工具集 (Coming Soon)”太长，占掉导航宽度。
- 顶部 nav 里有外链，也有 disabled button，但没有 About/Sites/Contact 的页面内导航。

根因位置：

- `components/layout/Header.tsx:7`：navItems。
- `components/layout/Header.tsx:65`：disabled 项显示 `${label} (Coming Soon)`。
- `components/layout/LanguageSwitcher.tsx`：两个完整文字按钮常驻。

建议做法：

1. 移动端隐藏 disabled 的 Tools，或者只显示 `Tools` 不显示 `(Coming Soon)`。
2. 语言切换改短：`CN` / `EN` 足够。
3. 首页 nav 应该优先滚到站内 section：Home、About、Sites、Projects、Contact。外链放到内容区 CTA。
4. 给当前语言和当前 section 做明确 active 状态。

## P2：内容源和个人信息有不一致风险

问题表现：

- `app/[locale]/page.tsx:15` 直接内联 translations。
- `app/i18n/zh-CN.json` 和 `app/i18n/en-US.json` 也有一份相似内容，但当前首页没有用它们。
- Blog 描述仍写 `NotionNext`，但工作台说明里 `jthewl-blog/` 是 Quartz + Obsidian。

建议做法：

1. 只保留一个内容源。要么用 JSON，要么删掉未使用 JSON。
2. 涉及个人链接、项目介绍、社交账号时，从工作台 consensus 数据同步，避免各项目各写一份。
3. 把 Blog 描述更新为当前真实技术栈。

## P2：项目卡片展示不够像作品集

问题表现：

- 桌面 Projects section 一行塞 5 个卡片，图片和标题都偏小。
- 部分游戏名很长，标题换行后缺少层级。
- 只有图片和名字，没有类型、年份、状态、核心卖点。

建议做法：

1. 首页只放 3 个精选项目，剩下的给 itch.io CTA。
2. 每张卡片至少补一句 1 行描述，比如玩法关键词或创作方向。
3. 第一张主推作品可以做大卡，其他作品做次级卡。
4. 保持 `object-fit: cover`，但给图片容器固定比例和 fallback 背景。

## P3：工程卫生

问题：

- `npm run lint` 会进入 ESLint 初始化交互，CI/本地都不能作为检查命令使用。
- `npm ci` 提示 `next@14.2.15` 有安全更新警告。
- `.nvmrc` 是 Node 18，但当前依赖里 `@types/node` 是 22，本地实际运行也是 Node 22。
- README 里关于 Next 安全修复的描述可能已经过期。

建议：

1. 补一个最小 ESLint 配置，让 `npm run lint` 非交互运行。
2. 升级 Next 到安全补丁版本，并同步 README。
3. 统一 Node 版本。要么项目明确用 Node 22，要么把依赖和本地运行回到 Node 18。

## 推荐执行顺序

1. 先修移动端横向溢出：SectionCard header、grid minmax、flex item min-width。
2. 再决定 snap 策略：移动端建议直接关闭，桌面再保留。
3. 调 hero：木星变成明确右侧主视觉，console 降级，移动端隐藏 console。
4. 清理 header：短语言切换、去掉 Coming Soon 长文案、补站内导航。
5. 统一内容源并修正 Blog 描述。
6. 最后做工程卫生：lint、Next 安全更新、Node 版本统一。

## 不建议现在做的事

- 不建议马上重写为全新视觉系统。当前主要是布局基础问题，不是需要推倒重来。
- 不建议先加更多动画。现在木星、CRT、scroll snap 已经足够多，先把层级和定位修稳。
- 不建议继续堆卡片。首页应该更像个人入口和精选作品，不是完整项目数据库。
